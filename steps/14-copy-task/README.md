# 첫 학습: 입력을 그대로 따라 쓰기

- 원본: [첫 번째 예제](https://dev-jonghoonpark.github.io/annotated-transformer-modern/#a-first-example) · [합성 데이터](https://dev-jonghoonpark.github.io/annotated-transformer-modern/#synthetic-data)

모든 부품이 모였다. 진짜 번역 데이터로 가기 전에 가장 쉬운 과제로 전체가 맞물려 돌아가는지 확인한다. **입력 숫자열을 그대로 출력하는 복사 과제**다.

- **`data_gen`**: 1~10 사이 난수 10개짜리 문장을 만든다. 첫 토큰은 시작 기호 1로 고정하고 src와 tgt를 똑같이 둔다.
- **`example_simple_model`**: 사전 크기 11, 2층짜리 모델을 만들어 Adam + `rate`(warmup 400)로 20 epoch 학습한 뒤, `greedy_decode`로 `[0, 1, ..., 9]`를 따라 쓰게 한다.

10단계에서 같은 크기의 모델이 무작위 토큰을 내놓던 것과 비교해 보자.

> 원본 노트북은 이 예제의 실행 줄(`execute_example(example_simple_model)`)을 주석 처리해 두어서 출력이 없다. 여기서는 CPU로 실제로 돌린 결과를 싣는다(시드 0).

## 실행 결과에서 볼 것

- epoch마다 한 줄씩 손실이 찍힌다. 2.9에서 시작해 0.1 안팎까지 내려간다.
- 학습률은 끝까지 **오르기만** 한다. 20 epoch × 20배치 = 400스텝이 warmup(400)과 같아서 내려가는 구간에 들어가지 못한다.
- 마지막 출력 `[0, 2, 1, 3, 4, ...]`는 앞쪽 두세 칸이 틀린다. 원본 README에 적힌 실행 결과도 `[0, 2, 3, 2, 4, ...]`처럼 앞쪽이 틀린다.

### 왜 앞쪽이 틀릴까

`data_gen`은 항상 1로 시작하고 1~10만 쓰는 문장을 만든다. 그런데 테스트 입력 `[0, 1, ..., 9]`는 **0으로 시작**한다. 0은 이 과제에서 패딩 id(`Batch(src, tgt, 0)`, `padding_idx=0`)라 학습 중 한 번도 입력으로 나온 적이 없는 토큰이다. 출력 아래쪽 실험에서 같은 설정으로 다시 학습한 모델에 학습 때와 같은 모양의 입력(`[1, 2, ..., 10]`)을 넣으면 완벽하게 따라 쓴다. 무작위 문장 100개 중에서는 88개를 정확히 복사했다. 모델이 못 배운 게 아니라 **학습 때 본 적 없는 입력**을 받은 것이다.
